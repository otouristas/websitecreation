# Website brand migration coverage — 2026-10-13

Untouched baseline at commit `ef4a43b0762266e4166d346f72897617ad478cba`. The 256-state matrix ran against the optimized brand build before the final contact definition-list, keyboard access to tables, localized 404 appearance and shared focus-state repairs. The 32 targeted final-release probes verified those repairs and selected rendered states after the release rebuild on localhost:8086. No production deployment is established by this report.

## Evidence and coverage

- Actual route inventory: 42 page files, with EN/EL consultant routes sharing one renderer. Data catalogs contain 12 services, 32 industries, 71 portfolio items, 74 blog posts, 9 tool pages and 3 comparison pages.
- Representative QA: 64 real URLs, including generic and bespoke service/industry renderers. 256 recorded states out of 256 planned states; dark/light × 390/1440px. This is template/variant coverage, not a test of every generated URL.
- Baseline: 6/6 states returned 200, with 0 horizontal-overflow failures. Baseline uses git archive plus the installed dependencies; all captures wait for hydration.
- Render failures / browser exceptions: 0. Horizontal page-overflow failures: 0. Visible brand-image loading failures: 0.
- Accessibility: 20 initial page-state axe audits, 2 mobile-menu audits, and 32 final-release targeted page-state audits. Initial audits found 4 contact route/state/rule combinations; all 4 were fixed and rechecked. Unresolved initial combinations: 0. Final-release violation combinations: 0.
- Axe color-contrast incomplete results: 54 audited states contain 10022 node occurrences requiring manual review. These are not passing contrast assertions. Automatic checks do not establish global WCAG AA certification.
- Final release: 32/32 targeted probes passed, including EN/EL contact, EN/EL arbitrary and dynamic-slug 404 routes, rendered warning notes, yearly/recommended pricing, FAQ toggle and focus/error-border style probes.
- Screenshots cover selected shared templates, with full-page dark desktop references and viewport images in other theme/width states. Machine records cover the remaining matrix.

Evidence in the local task deliverables: `before/`, `after/`, `after/qa-results.json`, and `2026-10-13-coverage.csv`. The QA runner lives outside the implementation checkout under `work/websitecreation-brand-qa/`.

## Safety of local interactions

The browser blocked external requests, non-GET requests, and every /api request. QA changed local theme state, local filters, navigation menus, pricing periods and unsent form input only. It did not submit forms, send leads, open external accounts or perform paid live checks. Redirect tests used local HTTP requests with automatic following disabled.

## Limited responsive and zoom/reflow checks

24/24 limited responsive states passed at 360 and 768 CSS pixels in both themes. Surfaces: shared header/home, contact form, get-started form, pricing, help table and 404. These are representative EN states; this is not another whole-route matrix.

The isolated headless setup did not verify true browser zoom. A separately named layout-reflow emulation halves 768 to 384 CSS pixels while keeping DPR 1. This checks narrow layout behavior; it does not test browser-native zoom, physical text enlargement, rasterization, pinch scaling, or browser chrome.

12/12 additional emulated 200% layout-reflow states passed across the same six surfaces and both themes. Initial viewport: 768px; observed after native shortcut probe: 768px. DPR: 1→1; visualViewport scale: 1→1. The emulated mode uses 384 CSS pixels and DPR 1 and does not prove browser zoom or physical text enlargement.

Superseded intermediate failures are retained under superseded/; they are not the final acceptance record. The final records are after/targeted-final-results.json and after/responsive-final-results.json.
