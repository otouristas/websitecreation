## Non-negotiable implementation rules

1. One token source: `tokens/brand.tokens.json`. Generate CSS, TS and Swift from it. Run `python3 scripts/sync_tokens.py --check` to catch drift. No route-level ad hoc hex values. Document artwork, external-brand, heatmap and customer white-label exceptions.
2. Mostly neutral surfaces and readable type. Gradient is for the logo and restrained accents, not every button/card/title. No neon/glow everywhere. Primary CTAs use the solid action/foreground pairs above; never white small text on bright cyan/mint. Decorative dividers are not the sole boundary of an input. Focus needs a visible offset gap and non-color cues.
3. Inspect the current Tailwind/shadcn variable contract: full hex values cannot be pasted into an `hsl(var(--primary))` channel variable. The package includes a specific HSL-channel adapter; full-color/OKLCH projects need their own semantic mapping. Keep one existing light/dark/system controller. Include sidebar, dialogs, portals, charts, tooltips, autofill and first-paint/hydration behavior.
4. Reuse the correct on-light/on-dark lockup for the ACTUAL surface. Compact nav/favicon/app icon uses standalone A. Preserve aspect ratio, clear space and accessible names. Repeated inline SVGs need unique gradient IDs or image references. Tagline is optional marketing copy, not required in nav or app icon.
5. For iOS, use dynamic sRGB semantic colors, keep native typography/navigation and accessibility. Inspect actual asset-catalog/Icon Composer setup. Opaque 1024x1024 masters are square and unmasked; the OS supplies corner masking. The package does NOT include a compiled .icon project or a verified Xcode build. Validate dark, clear and tinted appearances in current tooling. The legacy ios/DESIGN_SPEC.md color table is superseded by this brand decision, but its working UX/features/data logic are not.
